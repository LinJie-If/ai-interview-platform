# Documentation Rule (Strict)

## Rule
For EVERY code change or completed feature, you MUST generate a Markdown document.

## Requirements
After modifying code, ALWAYS output a Markdown document with:

### 1. What was done
- Describe the feature or change

### 2. Files changed
- List all modified or created files

### 3. Module explanation
- Explain each module/function changed
- What it does
- Why it exists

### 4. Logic explanation
- Explain the core logic in simple terms

### 5. How to use / test
- How I can verify this works

## Enforcement
- This step is MANDATORY
- If no documentation is provided, the task is NOT complete
- Documentation must be output EVERY TIME after code changes


Before coding, summarize the task in your own words.
